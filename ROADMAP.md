# План развития

Разработка идёт от воспроизводимого локального цикла к проверке интеграций и первому стабильному выпуску. Состав этапов уточняется по результатам реализации и испытаний.

| Этап | Результат | Статус |
| --- | --- | --- |
| **01 · Проектирование** | Модель данных, границы модулей, контракты API и критерии проверки | В работе |
| **02 · Локальная реализация** | Стенд, доступ, документы, редакции, подписание и тестовые адаптеры | Запланирован |
| **03 · Проверяемость и устойчивость** | Экспорт доказательств, независимая проверка, повторы, гонки и восстановление | Запланирован |
| **04 · Интеграционные испытания** | Развёртывание на тестовой инфраструктуре и проверка совместимости адаптеров | Запланирован |
| **05 · Первый релиз** | Самостоятельная установка, документация, проверка безопасности и правила обновления | Запланирован |

## Ближайшие задачи

- Определить модель документов, редакций, участников и подписей.
- Зафиксировать контракты API и внешних адаптеров.
- Подготовить воспроизводимый локальный стенд с синтетическими данными.
- Реализовать серверные проверки доступа и изоляции организаций.
- Проверить неизменяемость файлов, повторы запросов и конкурентное подписание.

## Принцип локальной разработки

Основной цикл должен работать локально без зависимости от доступности внешнего поставщика. Имитаторы реализуют те же контракты и воспроизводят ошибки, истечения и повторы; проверки доступа и доменной модели остаются обязательными.

Тестовые подтверждения имеют собственное происхождение и не принимаются как рабочие доказательства. Проверка адаптера на реальном сервисе проводится отдельно от локальной приёмки.

Подробнее — в [руководстве по разработке](docs/development.md).

## Критерии первого релиза

- Основной цикл проходит интеграционные и негативные тесты.
- Комплект доказательств экспортируется и проверяется независимо.
- Самостоятельная установка воспроизводится по документации.
- Проверены безопасность, восстановление данных и ограничения эксплуатации.
- Совместимость заявленных интеграций подтверждена испытаниями.
- Опубликованы версия, изменения и требования к обновлению.

Предложения по развитию можно обсудить в [Issues](https://github.com/prodirai/documata-core/issues).
