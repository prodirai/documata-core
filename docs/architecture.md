# Архитектура

Documata Core проектируется как самостоятельное ядро документооборота с версионированным API. Этот документ описывает целевую модель первого релиза.

## Жизненный цикл документа

```text
Документ → Зафиксированная редакция → Подписание → Комплект доказательств
```

Документ объединяет редакции и связанные материалы. Каждая редакция хранит собственный исходный файл и контрольную сумму. Подпись относится к определённой редакции; последующие изменения создают новую редакцию и сохраняют предыдущую историю.

## Основные модули

| Модуль | Ответственность |
| --- | --- |
| Документы | Исходные файлы, редакции, связи договоров и приложений |
| Доступ | Участники, организации, роли и разрешённые действия |
| Подписание | Последовательность действий и атомарная фиксация результата |
| Доказательства | События, контрольные суммы, экспорт и проверка |
| API | Контракты интеграций и совместимость версий |

## Инварианты

1. Доступ проверяется на сервере для каждой операции и каждого документа.
2. Данные организаций изолированы, включая файлы, поиск и фоновые задачи.
3. Подписанный исходный файл не изменяется; новая редакция получает собственную историю подписания.
4. Подтверждение успешного подписания выдаётся после надёжного сохранения результата и его доказательств.
5. Повтор запроса не создаёт повторную подпись или дублирующее событие.
6. Экспорт позволяет проверить связь результата с исходным документом.

## Развёртывание

Целевая конфигурация: API, транзакционная база данных, закрытое объектное хранилище, фоновые обработчики и минимальный клиент.

База отвечает за согласованность состояния, объектное хранилище — за файлы, обработчики — за длительные операции. Внешние сервисы подключаются через адаптеры с определёнными границами доступа.

## Интеграции

API версионируется независимо от пользовательских приложений. Совместимость проверяется контрактными тестами. Приложения фиксируют используемую версию ядра, а изменения контрактов сопровождаются описанием миграции.

Контроль доступа к документам остаётся обязанностью ядра. Приложения могут добавлять собственный интерфейс, тарифы и рабочие процессы.
