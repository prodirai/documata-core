# Подключение ядра к серверному приложению

Documata Core поставляется как библиотека Python. Внешнее приложение отвечает за HTTP-сервис, установление личности, проверку полномочий, доставку, эксплуатацию и выбор режима провайдеров. В текущей реализации реестр создаёт свидетельства с признаками `environment=local` и `assurance=simulated`. Первый серверный прогон выполняют на синтетических данных.

## Подготовка версии

Зафиксируйте полный Git SHA ядра в репозитории приложения. Из этого же checkout подготовьте пакет и выполните тесты на целевой Linux-платформе с Python 3.12+, OpenSSL и libseccomp2. Проверка хешей зависимостей нужна и при установке в закрытом контуре.

```sh
git rev-parse HEAD
python3 -m venv .venv
.venv/bin/pip install --require-hashes -r requirements.lock
.venv/bin/python -m unittest discover -s tests -v
```

## Серверная приёмка

1. Разверните проверенную версию под выделенным пользователем. Заведите новый каталог данных и собственные ключи для каждой среды. Доступ к сервису на время приёмки ограничьте командой проекта.
2. Проведите обмен в двух сессиях. Проверьте доступ к редакции, отказ при смене полномочий, привязку проявленной воли к файлу, повтор после потери ответа и выдачу экземпляра второй стороне.
3. Сохраните ZIP доказательств и получите публичный ключ реестра по отдельному доверенному каналу. Выполните проверку, сохранив SHA сборки и результат.
4. Испытайте согласованное резервирование реестра, файлов и ключей и восстановление в отдельный каталог. Повторно проверьте доступ и экспорт ранее завершённой редакции. При откате приложения сохраняйте уже подтверждённые записи.

```sh
.venv/bin/python -m documata.export evidence.zip --require-envelope-seal --trusted-key registry.public
```

## Перед рабочими операциями

Выпуск для реальных подписей требует реализации рабочего происхождения доказательств, проверки ответов провайдеров, изоляции рабочих ключей, принятой модели времени и актуальных полномочий. В интегрирующем приложении также должны быть согласованы тексты, виды документов, основания обработки, поддержка, сроки хранения, план аварийного восстановления и измеренные критерии выпуска. После изменения версии ядра повторите сквозной обмен, проверку ранее выпущенных комплектов и восстановление. [Формат доказательств](evidence-format.md)
